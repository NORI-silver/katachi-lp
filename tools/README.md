# 作り直し方

前提: 企業DB・マッチングエンジン（katachi-matching）が `km/` にあり、`real.db`・`fx.db` にデータを入れてマッチ結果を作ってある（`collar_real.json` `mimamori.json` `bike.json` `collar_fx.json`）。

```
S=作業フォルダ（km/ とマッチ結果と、このフォルダのファイルを置く）
cp template.html $S/v2.html
python3 build.py $S        # マッチ結果と企業データ → data.js
python3 assemble.py $S     # v2.html + data.js + i18n.py → katachi.html（claude.ai の試作版にも使う）
python3 guided_data.py <katachi-matching>/data/real/companies.csv <katachi-matching> <リポジトリ>/data/companies.json   # 文章の読み取り・選択式で使う会社一覧（8千社、使うときだけ読み込む）
python3 prod.py $S <リポジトリ> <受付URL>   # → index.html（GA・受付先・OGP・本文つき）
python3 legal.py <リポジトリ>               # 利用規約・プライバシーポリシー・404
python3 public_records.py <katachi-matching>/data/gbiz <リポジトリ>   # 国の公開データ（gBizINFOの認定・表彰・補助金・特許）→ data/rec/（会社を開いたときだけ読み込む）
python3 seo_pages.py <リポジトリ>             # ガイド記事・sitemap.xml・llms.txt（本文は guides.py）
```

## 概算の目安（`estimates.py`）
「概算・最低ロット」タブ、選択式の候補画面（`#gEst`）、文章入力の結果画面（`#mEst`）に出す数字。公開されている料金表・記事に書かれた数字だけを、出典URL・確かさ（公式の料金表／報道・記事／業者・まとめサイト／根拠の記載がない目安）付きで持つ。`build.py` が `est` として data.js に入れ、企業DBの最小ロット（掲載情報）も工程ごとに集計する。画面からは `window.KATACHI_EST_CARD(工程コード, 数量の上限, 数量)` でカードのHTMLを得られる。数字を足したら出典を必ず付け、文言は `T_EST`/`T_ROWS` に英語・中国語も足す（`i18n.py` が読み込む）。確定見積ではないので、作った数字・推測の数字は入れない。

## 製品イメージ案（`concepts.py`）
文章入力の結果画面の最初に出す「製品イメージ案」（外観の図・サイズ・重さ・素材・動力・想定スペック・主な機能・方向性・試作で確かめること・作り方）。AIのAPIは使わず、製品の種類ごとの典型例をキーワードで選んで出す（法面の草刈機、草刈ロボット、電動台車、ドローン、首輪型、ウェアラブル、IoTセンサー、ライト、樹脂小物、バッグ、ウェア、化粧品、食品、グッズ、家具、汎用の機械・電子機器）。画面では「AI推定・たたき台」と明記し、最終判断は工場・専門家とする。当たらないときは、AI相談の質問文で「製品イメージ案を2〜3通り」と頼む。
- 文言は日英中の組で `concepts.py` に書く。`assemble.py` が日本語を `template.html` の `__CONCEPTS__` に入れ、`i18n.py` が英中を辞書に足す。
- 図は `template.html` の `CFIG`（種類ごとのSVG）。寸法は数字だけ（mm）。
- 種類を足すときは、上から順に当たるので、細かい種類（法面の草刈機）を広い種類（草刈機）より上に置く。
- どの典型例にも当たらないときは、汎用ロジック（`concepts_generic.py`）で必ず案を出す。文章の「形の言葉」（スロープ・ステップ・ハウス・柵・ベッド・マット・カバー・台・箱・金具・食器・おもちゃ・道具、どれでもなければ汎用）と、条件（プール・水まわり・屋外・ペット・揺れない・折りたたみ・子ども・高齢者・電気・口に触れる）、数字（乗る重さ kg、高さ・幅・長さ・大きさ cm）を組み合わせて、図・寸法・素材・機能を組み立てる。条件は典型例の案にも足す。
- 「相談しながら詰める」（AIなし）: 形に合う質問（使う場所・使う人・乗る重さ・段差の高さ・大きさ・大事なこと・予算）を1つずつ出し、答えを「【相談で決めたこと】」として依頼の文章に足して、案と候補の会社を組み直す。文章で答え済みの質問は出さない。
- 参考品のURL: 「既製品をもとに作る」の欄や文章にURL（`wancare.jp` のように https なしでも可）があれば、進むときに受付（`backend/forms.gs` の type:`peek`）がそのページを1回読み、題名・説明・商品名・分類・パンくずだけを返す。読めたら「【参考品のページから読み取った内容】」として依頼の文章に足し、製品の種類の読み取りに使う。読めなければ結果画面で「書き直す」をすすめる。受付を直したら新バージョンのデプロイが要る。
- 「内蔵AIと話す」: パソコンのChrome（Prompt API、`LanguageModel`）があるときだけ②にボタンを出す。AIは端末の中で動き、KATACHIの費用も外部送信もない。JSONの形（`LAI_SCHEMA`）で返事・製品イメージ案（名前・寸法mm・素材・機能・確かめること）・決めたことを受け取り、案を差し替え、決めたことは「【相談で決めたこと】」に足して候補の会社も組み直す。対応する言語は日本語・英語（中国語の画面では英語で話す）。スマホ・ほかのブラウザでは出さず、「質問に答える」で詰める。会話欄の横（スマホは上に固定）に「いまの製品イメージ案」（図・寸法・素材）を出し、変わった項目を黄色で示す。返事が来てもページは描き直さず、案だけその場で差し替える（候補の会社は「会社を探す」で組み直す）。テストは `LanguageModel` をまねたものを Playwright で差し込んで確かめる。
- 3D表示: 製品イメージ案の図は「3D／寸法図」を切り替えられる（既定は3D）。three.js（MIT、`vendor/three-0.149.0.min.js`。外部のCDNから読まないので外部送信は増えない）を案が出たときだけ読み、`v3build` が図の種類（`fig.k`）・寸法(mm)・「主な素材」の言葉から箱・円柱・回転体を組み合わせて立体にする。ドラッグで360度回す（スマホは横になぞると回り、縦はスクロール）、＋－で拡大縮小。内蔵AIとの会話で寸法・素材が変わると3Dも作り直す。WebGLが使えない端末では寸法図だけ。形の種類を足したら `CFIG`（寸法図）と `v3build` の `K`（3D）の両方に足す。

## 作例ギャラリーと作例のページ（`ideas.py`）
トップの「何をつくるか、まだ決まっていなくても」（業種を選ぶと作例が出る）と、作例ごとの詳しいページ `/idea/<k>/`・一覧 `/idea/`。
- 作例・業種・図（線のアイコン）・作り方の型（流れ・決めること・確かめる表示）は `ideas.py` に書く。`assemble.py` が `__IDEAS__` に入れ、`i18n.py` が英中を足す。ページは `seo_pages.py` が作る。
- 目安は `estimates.py` の出典つきの行だけ。許可・表示の説明は、出典つきのガイド記事に合わせてリンクする。実在企業の事例・見積は作らない。
- 作例を足したら、トップで「この内容で探す」を押して工程が特定できる（フォールバックにならない）ことを確かめる。
- ガイド記事の最後には、そのガイドを参照する作例（「このテーマの作例」）が自動で出る。

## 一社か組み合わせかの比較と、料金・品質・納期の並べ替え（`company_signals.py`）
文章入力の結果（`#match`）に「一社にまとめるか、組み合わせるか」（`#mPlans`）を出し、2つの案を並べて比べ、どちらか・両方の会社を選んで見積依頼に進める（依頼書の「頼み方」に入る）。一社案は対応工程の多い会社から、組み合わせ案は工程ごとの先頭の会社から作り、どちらも並べ替え・絞り込みに合わせて入れ替わる。
- 並べ替え（おすすめ／料金を抑えやすい／品質の根拠が多い／納期が短くなりやすい）・届け先・絞り込みは、文章入力の結果と「選んで探す」の両方に出る（`axBar`）。
- 点数や星は出さない。会社ごとに「料金・品質・納期」の根拠を出典つきで出し、根拠がなければ「見積で確認」。料金＝最小ロット（掲載情報）、品質＝公式サイト等で確認・説明文の認証の記載・試作相談・国の公開データ（補助金の採択・従業員数）、納期＝所在地（届け先と同じ県・地方、海外）と掲載された納期。
- 材料は `data/companies.json` の列14。`python3 company_signals.py <katachi-matching> <リポジトリ>/data/companies.json` で今のファイルに足せる（`guided_data.py` で作り直すときも自動で付く）。gBizINFOとは「社名＋都道府県」の完全一致だけで結ぶ。
- 実際の見積・回答実績が集まったら、それを料金・納期の根拠に足す（作った数字は入れない）。

## 完成品メーカー（`makers.py`）
③「会社を選ぶ」で、文章が製品の種類（犬・猫の車椅子、ペットの首輪・服、電子機器のODMなど）に当たったら、工程ごとの組み合わせより先に「完成品のメーカーに1社で頼む」を★おすすめで出す（Nori 2026-11-14「犬の補助輪とか普通一つの会社で作ってるよ」）。組み合わせ案は「部品から作る案」として切り替えて見られる。
- 種類ごとに、依頼の文章に当たる言葉（`idea`）・DBの概要に当たる言葉（`db`）・手で集めた会社（`rows`、companies.json と同じ行の形）を書く。`assemble.py` が `__MAKERS__` に入れる。
- 手で集めた会社は、出典URLと確認日を付ける。公式サイトで確かめた会社だけ確かさ `pub`、まとめ記事だけの会社は `unk`。OEMを受けるかなど書いていないことは書かない。
- 同じ会社を企業DB（katachi-matching）にも `data/real/batch_finished_goods.jsonl` で入れてある。
- 組み合わせ案では、組立・検査の工程がなければ「取りまとめ役」（組立と品質の責任を持つ会社）を必ず1社足し、見積の送り先の先頭に入れる（`integOf`）。

## 製品イメージ案の回帰テスト
- 長い仕様文で違う種類の製品にならないかを確かめる。`tools/tests/specs/` に入力文と期待する種類（`cases.json`）がある。
- リポジトリのルートで `python3 -m http.server 8765` を動かし、`node tools/tests/concept_cases.js` を実行（Playwright、ローカル）。
- 仕様文に【製品名】があればその名前で種類を決め、種類にない製品は名前のまま、構成・外観（車輪・脚・担架・昇降など）から形を組む（`specRead`・`specConcept`、3Dは `parts`）。

## 製品仕様DBと、お使いのAIでの整理（AIのAPIは使わない＝費用ゼロ）
- 製品仕様DB：`python3 tools/product_db.py .` で `data/products.json` を作る（作例44本＋全業界のよくある製品＋製品イメージ案の種類）。画面は送信時に読み込み、製品名（なければ冒頭の1行）に近い製品を当てて、工程・最小ロット・法規制を出典つきで出す。総務省「日本標準商品分類」（`tools/data/jscc_1990.tsv`、e-Stat の分類検索から全件37,041項目を取得、再掲は除く）も取り込み、分類ごとの工程・法規制・業界は `tools/jscc_rules.py` で決める（扱わない分野は None で除外）。財務省「輸出統計品目表」2026年1月版（HS、`tools/data/hs_2026.tsv`、9,796行）も取り込み、分類にない今の品（スマートフォン・リチウムイオン蓄電池など）を補う（規則は `tools/hs_rules.py`、コードは `H`＋4桁）。言い換え語（ボールベアリング→玉軸受 など）は `tools/product_syn.py`（右の名前が分類・品目表の語と同じでないものは作るときに捨てて表示）。通販・クラファンでよく見る新しい品（ポータブル電源・推し活グッズ等）は `product_db.py` の「新しい製品」に足す。約2.6万品目を当てられる。当て方の回帰テストは `node tools/tests/pdb_cases.js`。数字は `estimates.py` の出典つきの行、法規制は `REG` の公的機関のページだけ。構成・素材は「AI推定（よくある例）」と明記。
- 長い仕様文は、AI相談の質問文の最後で、決まった項目のJSON（`SX_TPL`）を出すよう頼む。貼り戻すと `sxParse` が読み、根拠の原文（quote）が利用者の文章に見つからない値は「要確認」にする。結果はこの端末（localStorage）に保存し、同じ文章では保存済みを使う。
- 受付への保存（`backend/forms.gs` の type:`spec`／`specsave`、シート「仕様読み取り」）は、受付を新しいバージョンにデプロイしてから `template.html` の `SPECDB` を true にする。「DBの一致」が空の行はDBにない新しい製品なので、見直して `product_db.py` に足して育てる。

## 工場向け仕様書（`fspec.py`、AIのAPIは使わない）
- 文章を、工場が見積に使う形（共通の項目＋品目別9種：電子・金属・樹脂・布・ペット・食品・化粧品・木工・グッズ）に並べ直す。項目・必須・選択式の質問・工場への質問は `tools/fspec.py` に書き、`python3 tools/fspec.py .` で `data/fspec.json`（MCP・APIと共有する形）を作る。画面へは `assemble.py` が `__FSPEC__` で入れ、訳は `T_FSPEC` を `i18n.py` が取り込む。
- 埋め方は `template.html` の `fsBuild`：選択式の回答 → 利用者の文章・貼り戻したJSON（根拠の原文を確かめ済み）→ 製品DB（公的な出典つき）→「わからない」と答えた項目だけ似た製品の目安（仮）→ 要確認。確かさの重みは 原文・回答・製品DB=1、仮=0.5、要確認=0。必須項目の平均が「工場に出せる度」で、75%以上は見積に出せる、図面・3D・現物がない形のある品は「設計の見積から」。
- 足りない必須項目は選択式で最大5問ずつ聞き、答えはこの端末に保存する。工場への質問は見積依頼の「工場向け仕様書」欄に自動で付く。設計の下書きとして、製品イメージ案の3D（STL）と寸法図（SVG）を保存できる。
- 貼り戻しJSON（`SX_TPL`）には scope・due・budget・docs・category_items（品目別の項目名＋値＋根拠の原文）も入る。受付の保存（`backend/forms.gs` の specsave）は今の項目だけを保存する。
- 回帰テスト：`node tools/tests/fspec_cases.js [URL] [スクショのフォルダ]`。
